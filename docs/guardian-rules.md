# Guardian Rules

GuardianRail uses two kinds of rules:

1. **Default calibrated rules** committed in `artifacts/guardian_rules_layer12.json`.
2. **Custom operator rules** added through the Streamlit **Custom Guardian Features** panel.

Both rule types are evaluated against real or mock Guardian features and can drive allow/refuse/escalate policy actions.

## Default Rule Artifact

Generated by:

```bash
python scripts/calibrate_guardian_rules.py \
  --model google/gemma-3-12b-it \
  --sae-repo google/gemma-scope-2-12b-it \
  --sae-path resid_post/layer_12_width_16k_l0_small \
  --layer 12 \
  --feature-ids 7455,64,13763,166,10372
```

Artifact:

```text
artifacts/guardian_rules_layer12.json
```

## Default MVP Policy

```text
Normal support query:
  no monitored feature crosses threshold
  action = allow

Prompt injection / unauthorized transaction:
  one or more guardian features cross threshold
  action = refuse

Social pressure / unusual authorization:
  one or more guardian features cross threshold
  action = escalate
```

The real backend also uses prompt text to choose escalation for obvious social-pressure cases. That is intentional for the demo: the SAE feature values provide observability, while the controller policy decides the business action.

## Custom Rules

Custom rules are created in the Streamlit app under **Custom Guardian Features**.

A rule has:

```text
feature_id
label
threshold
action: monitor | refuse | escalate
intervention: monitor | clamp | boost | pause
clamp_target
source = custom
enabled = true
```

Examples:

```text
feat_166
label = operator-selected hidden/system instruction clamp
threshold = 1.0
action = refuse
intervention = clamp
clamp_target = 0.0
```

```text
feat_64
label = unauthorized account access
threshold = 120.759
action = escalate
intervention = pause
```

Custom rules override default rules with the same feature ID.

## Text To Feature Finder

The finder is in the same Custom Guardian Features panel. It searches:

```text
artifacts/guardian_candidates_layer12.json
artifacts/guardian_rules_layer12.json
```

Good demo query:

```text
system prompt override
```

Expected top result:

```text
feat_166 - hidden/system instruction request
```

Click:

```text
Clamp feat_166
```

This adds a custom rule that clamps only that selected feature in the intervention ledger.

## Intervention Semantics

Current intervention types:

```text
monitor
  log feature crossing without changing action

clamp
  policy-layer clamp; show feature before -> target in Feature Clamp Rail

boost
  policy-layer boost; used for the refusal rail or selected custom features

pause
  stop/route to human escalation path
```

Important:

```text
These are policy-layer interventions in the MVP. They do not yet decode SAE feature edits back into the model residual stream.
```


```bash

  --server.address=0.0.0.0 \
```
